# Security Policy

At **KodeDock**, security and trust are foundational to our mission. Because KodeDock verifies, distributes, and cryptographically licenses production software architectures and codebases, we treat security vulnerabilities with the highest priority.

---

## 1. Supported Versions

Security updates and patches are actively provided for the following releases:

| Version | Supported | Notes |
| :--- | :--- | :--- |
| `1.x.x` (Current Main) | :white_check_mark: Yes | Actively maintained production release |
| `< 1.0.0` | :x: No | Pre-release alpha/beta builds |

---

## 2. Reporting a Vulnerability

If you discover a security vulnerability within KodeDock or any of its applications (`store`, `studio`, `portal`, `www`, `api`), please report it privately. **Do NOT open a public GitHub issue.**

### How to Submit
- **Email**: Send detailed disclosure reports to **security@kodedock.dev**.
- **Subject**: `[SECURITY VULNERABILITY] <Brief Description>`
- **Contents**:
  - Description of the vulnerability and its potential impact.
  - Step-by-step reproduction instructions or proof-of-concept (PoC).
  - Affected components, services, or endpoints.
  - Any proposed mitigations or fixes.

### Response Timelines
- **Initial Acknowledgement**: Within **24–48 hours** of report receipt.
- **Triage & Assessment**: Within **3–5 business days**.
- **Fix & Disclosure**: We aim to release a patch within **14 days** of triage, followed by coordinated public disclosure.

## 3. Cryptographic Security Standards

KodeDock adheres to strict cryptographic design principles:

1. **Ed25519 Cryptographic Licensing**:
   - Software licenses generated by the licensing engine are signed using Ed25519 digital signatures.
   - License keys are tamper-evident and can be verified offline by developer consumers using the public key.
   - Private signing keys are stored exclusively in secure environment variables or hardware key vaults—never committed to source control.

2. **Database & SQL Injection Immunity**:
   - Zero raw SQL string concatenation. All database operations strictly use parameterized queries (`$1, $2, ...`) via `pg.Pool`.
   - All external inputs are validated and sanitized through Zod schema boundaries at the API gateway layer (`api/`).

3. **Authentication & Password Storage**:
   - User authentication is powered by **Better Auth** with Scrypt password hashing and high work factors.
   - Session tokens and JWTs utilize rotating signing secrets with strict expiration windows.

4. **Expiring Download Signatures**:
   - Repository code downloads and release archives are delivered through signed Cloudflare R2 URLs that expire automatically after **60 seconds**, preventing link-sharing and unauthorized redistribution.

## 4. Safe Harbor Policy

We consider security research conducted under this policy to be:
- Authorized under applicable anti-hacking laws.
- Exempt from copyright or anti-circumvention claims.
- Eligible for acknowledgment in our release notes and contributor hall of fame.

We ask that researchers:
- Make a good-faith effort to avoid privacy violations, data destruction, and service disruption.
- Only interact with test accounts you own or have explicit permission to test.
- Give us reasonable time to remediate before public disclosure.

Thank you for helping keep KodeDock and the developer software ecosystem secure!
